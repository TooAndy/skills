# Agent Report Deep Dive

阶段 3：对阶段2筛选出的 TOP 10 候选进行深度剖析。

## 硬性约束

1. **必须等阶段2完成** - 只有 candidates/ 中有 10 个候选才能开始
2. **必须剖析 10 个** - 不能少
3. **逐个写入 deep_dive/** - 每完成一个就写入，不要等全部完成再写

## 强制联网研究要求

**每篇 deep dive 必须满足以下条件，否则报告不可信**:

### 信息来源要求

1. **必须使用 browse 工具访问至少 2 个来源**:
   - 主要来源：产品官网 或 GitHub README
   - 辅助来源：官方文档 或 技术博客

2. **禁止的行为**:
   - ❌ 禁止在未经实际浏览的情况下写入 deep dive
   - ❌ 禁止使用训练数据"补充"缺失信息
   - ❌ 禁止基于猜测写入技术架构、工具集等信息
   - ❌ 如果信息确实找不到，标记为"需要进一步调研"，不要编造

3. **信息来源验证**:
   - 技术架构必须来自 README/官网
   - 工具集必须来自官方文档
   - 基座模型、编排框架必须有据可查

### 浏览执行流程

对每个候选案例执行以下流程：

```
1. 使用 gstack browse 打开 GitHub README
2. 提取：架构图、技术栈、工具集
3. 使用 gstack browse 打开产品官网（或官方文档）
4. 提取：核心功能、部署方式、使用限制
5. 如果信息不足，使用 web_search 搜索补充
6. 写入 deep_dive/candidate_XXX.md，包含真实来源链接
```

### deep_dive 文件内容要求

每份 deep dive 必须包含：

```markdown
## 来源信息

- 主要来源: [URL] - [提取的关键信息]
- 辅助来源: [URL] - [提取的关键信息]
- 参考来源: [URL] - [提取的关键信息]
```

## 输入检查

读取 `reports/{year}-{month}/candidates/`，检查：
- 必须有 10 个候选文件
- 如果不足 10 个，报错要求重新执行阶段2

## 工作目录

```
reports/{year}-{month}/
├── candidates/              # 输入: TOP 10 候选
│   ├── candidate_001.json
│   └── ...
└── deep_dive/               # 输出: TOP 10 深度剖析（逐个写入）
    ├── candidate_001.md
    └── ...
```

## 深度剖析信息来源（按优先级）

1. **产品官网** - 获取核心功能和使用场景
2. **GitHub README** - 获取技术架构和实现细节
3. **官方文档** - 获取详细的 API 和使用方式
4. **技术博客** - 获取架构解读和最佳实践
5. **代码仓库** - 获取实际实现（必要时）

## 深度剖析规则

**关键原则**: 如果某信息缺失，继续搜索其他来源补充，不要编造。

- 产品信息不足 → 使用 gstack browse 访问 GitHub、博客
- GitHub 信息不足 → 使用 web_search 搜索技术文章
- 所有来源都不够 → 标记"需要进一步调研"，不要写入猜测的信息

**逐个写入**: 每完成一个候选的深度剖析，立即写入 `deep_dive/candidate_XXX.md`。

## Incident 案例引用

以下 incident 案例作为"风险引用"，不作为独立案例：

| Incident 案例 | 作为引用到 |
|---------------|-----------|
| AI agent 删库 | 所有涉及高风险操作的案例 |
| AI agent 发黑料 | 所有涉及内容生成的案例 |
| AI agent shame maintainer | 所有涉及自动化提交的案例 |

引用格式：
```
**警示**: 【AI agent 删库事故】任何高风险操作（交易、删除）都需要人工确认
```

## 历史案例更新剖析

如果被选入的案例在历史报告中已剖析过，应聚焦于更新点：

### 识别历史案例

1. 检查 `reports/` 下历史报告是否包含相同案例
2. 对比版本号/发布时间，确认是否有重大更新
3. 读取历史 deep_dive 文件，了解已剖析内容

### 差异化剖析框架

**历史案例 vs 新案例**：

| 维度 | 新案例 | 历史案例（有重大更新） |
|------|--------|----------------------|
| 业务场景 | 完整介绍 | 聚焦更新场景 |
| 技术架构 | 完整剖析 | 聚焦变化部分 |
| 差异化对比 | N/A | 必须与历史版本对比 |
| 团队借鉴 | 完整借鉴 | 聚焦新增能力 |

### 剖析格式（历史案例更新）

```markdown
# {案例名称} v2.0 更新剖析

## 更新概述

相比 v1.0（{历史报告链接}）的重大变化：
- {更新点1}
- {更新点2}
- {更新点3}

## 技术架构变化

**变更点**: {描述}
**新增组件**: {描述}

## 团队借鉴

**可直接借鉴**: {新功能/新架构}
**需谨慎借鉴**: {与 v1.0 相同的部分}
```
